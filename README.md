# Living Village · כפר חי

**מדריך מעשי להחייאת מפה מצוירת: דמויות שהולכות, רצות, יושבות, ישנות ומשחקות.**

הלקחים כאן נאספו בזמן העבודה על מפת הקמפינג באפליקציית אינדינגב 2026
([tom-lev/indienegev-2026](https://github.com/tom-lev/indienegev-2026), הקבצים `app/build.py` ו־`app/src/map.js`).
בכל נושא יש שלושה חלקים: מה עובד, מה לא עובד ולמה, והמספרים שנבחרו בסוף.
עותק מלא של הקוד נמצא בתיקייה [`code/`](code/) (ראו סעיף 11).

> **דמו חי:** [`demo/index.html`](demo/index.html) – מפה וקטורית (SVG) של כפר עם דמויות שהולכות על הדרכים, כלב עם רצועה, ילדה עם בלון,
> רכבים, חיות במכלאה וברווזים באגם. אפשר להתקרב פי 24 בלי לאבד חדות, וללחוץ על דמות כדי לעקוב אחריה.
> אין תלויות ואין בנייה: פותחים את הקובץ בדפדפן. הוא מתפרס ל־GitHub Pages דרך `.github/workflows/pages.yml`.

## 1. עקרונות יסוד (הכי חשוב)

1. **צעדים לפי מרחק, לא לפי זמן.** זה ההבדל בין דמות שהולכת לבין דמות שמחליקה כמו על מסוע.
   התמונה במחזור ההליכה נבחרת לפי המרחק שהדמות עברה בפועל: `phase += ds / strideLength`.
   כך כף הרגל שעל הקרקע נשארת נעוצה במקום, בכל מהירות, גם בהאטה, בהאצה ובריצה.
2. **בונים לפי מיקום כפות הרגליים, ולא לפי זוויות של מפרקים.** מגדירים איפה כל כף רגל נמצאת בכל רגע במחזור,
   ומחשבים את הברך בקינמטיקה הפוכה (IK) של שני מקטעים. גובה הירך נובע מאורך הרגל, ומכאן מגיעה
   תנועת העלייה והירידה הטבעית מעצמה.
3. **החפץ צמוד לנקודה בשלד.** פריזבי, סיגריה או בלון: בזמן בניית גיליון התמונות שומרים לכל תמונה את מיקום היד או קצה הסיגריה,
   והחפץ מצויר בנפרד בזמן ריצה, במיקום הזה בדיוק. כשהתמונה מתחלפת, מיקום היד מחושב באינטרפולציה
   בין שתי התמונות הסמוכות, כדי שהחפץ לא יקפוץ.
4. **אין "קפיצות" בשום מעבר.** כל מעבר צריך להתחיל בדיוק בתנוחה שבה הקודם נגמר: מבט, כיוון, עמידה/הליכה, זורק/תופס, יושב/עומד.
   בודקים זאת במדידה של המיקום פריים אחרי פריים, ולא רק בעין (ראו סעיף 9).
5. **מספיק יותר תמונות.** 6 תנוחות קבועות נראות כמו מצגת. 24–48 תמונות שנוצרות באינטרפולציה בין כמה תנוחות מפתח
   (עם האטה בכניסה וביציאה) נראות כמו תנועה.
6. **שומרים על הסגנון של הציור.** הדמויות מצוירות בצבע הדיו של הדמויות במפה (הצבע נלקח מדמות שנחתכה מהציור), מצוירות פי 8
   ומוקטנות עם טשטוש קל, כדי לקבל קצוות רכים כמו בציור.
7. **פחות זה יותר.** כל אפקט שנראה "מוגזם" נפסל: פעימה גדולה, אבק, גחליליות, זוהר על כל הגוף.
   אפקט טוב מורגש רק כשמסתכלים עליו.

## 2. ארכיטקטורה

```
build.py (Python + PIL, בזמן בנייה)          map.js (בזמן ריצה, בדפדפן)
───────────────────────────────            ──────────────────────────────
• חיתוך ציפורים/דמויות מהציור              • requestAnimationFrame אחד לכל סוג דמות
• גיליון תמונות פרוצדורלי (webp שקוף)      • מכונת מצבים לכל דמות
• JSON: מיקומי ידיים/קצות/פה לכל תמונה      • background-position = בחירת התמונה
• מטמון ב-assets/ (מחיקה = יצירה מחדש)     • transform בלבד (בלי layout)
• הכול מוטמע בקובץ HTML אחד                • WAAPI (element.animate) לחלקיקים
```

- **גיליון תמונות:** שורה לכל דמות ומבט, עמודה לכל תמונה. בוחרים תמונה עם `background-position`
  (ב־`%` על הציר האנכי: `row / (rows-1) * 100%`).
- **מטמון:** קובצי webp ו־json נשמרים בתיקיית assets. כדי ליצור דמות מחדש מוחקים את הקבצים שלה ובונים שוב.
- **עצירה:** כל לולאת tick בודקת `if (!document.contains(stage)) return;`. ביציאה מהמפה הלולאות נעצרות מעצמן,
  כך שמחוץ למפה הצריכה היא כ־0%. בכניסה מחדש מתחילים עם `cancelAnimationFrame(prevRAF)`.
- **`prefers-reduced-motion`:** כשהמשתמש ביקש פחות תנועה, אף אחת מהלולאות לא מתחילה.
- **עובד אופליין:** כל הקבצים מוטמעים כ־data URI, ואין בקשות רשת.

## 3. הליכה: מחזור הליכה פרוצדורלי

### הפרמטרים שנבחרו
| פרמטר | ערך | משמעות |
|---|---|---|
| `WALK_FRAMES` | 24 | תמונות למחזור (שני צעדים) |
| `WALK_IDLE` | 4 | תמונות עמידה: עומד, נושם, משען שמאלה, משען ימינה |
| `WALK_A` | 0.13 | חצי צעד ביחס לגובה הדמות |
| `WALK_KF` | 0.6 | קיצור פרספקטיבה במבט מלפנים ומאחור |
| `WALK_FOOT` | 0.9 | קו הקרקע בגובה התמונה |
| ציור | ×8 ואז הקטנה | `GaussianBlur(S*0.28)` ואז `LANCZOS` |
| פרופורציות (×H) | ראש 0.135, ירך 0.255, שוק 0.235, גו 0.295, כף רגל 0.085 | |

### מסלול כף הרגל (הלב של הכול)
```python
def foot(q, A, lift_h):
    if q < 0.5:                       # על הקרקע: זזה אחורה בקצב קבוע לגמרי
        return A - 2*A*(q/0.5), 0.0
    u = (q - 0.5) / 0.5               # באוויר: קשת קדימה
    return -A + 2*A*(1-cos(pi*u))/2, lift_h*sin(pi*u)

feet = [foot(wrap(ph + 0.5*k), A, lift) for k in (0, 1)]   # שתי רגליים בהפרש חצי מחזור
hipH = sqrt((L*0.992)**2 - fx_stance**2) + ankle_gap       # הירך נגזרת מרגל העמידה
knee = knee_ik(hip, ankle, Lt, Ls, forward=1)
```
- **ידיים:** הפוכות לרגל באותו צד (`armA = -24° * fx/A`), והמרפק מתכופף מעט כשהיד מאחור.
- **בוהן:** פונה מעט למטה כשהרגל באוויר.
- **נטיית הגוף:** כ־5° קדימה בהליכה, כ־1.5° בעמידה.

### שלושה מבטים
- **מהצד (0):** IK מלא, והיפוך אופקי עם `scaleX(±1)` לפי כיוון ההליכה.
- **מלפנים (1) ומאחור (2):** הרגליים זזות אנכית על המסך ומקוצרות (`×KF`), עם נדנוד קל של הירך לצדדים, והידיים בצדי הגוף
  (רווח קטן מהגוף). כשהיד מתנדנדת קדימה ואחורה היא מתקצרת ומתארכת: `cos(24° * fx/A)`.
- **מתי מחליפים מבט:** `side = |uy| <= |ux| * 1.15`, כלומר עד כ־49° מהאופק רואים את הדמות מהצד.
- **השהיית שינוי (hysteresis):** כיוון חדש נכנס לתוקף רק אחרי 9 פיקסלים של הליכה בכיוון הזה. אחרת הדמות "מתעוותת" בפינות.

### צעדים לפי מרחק (JS)
```js
w.phase += side ? ds*|ux| / (4*w.a)          // מהצד: 4A מרחק לכל מחזור
                : ds*|uy| / (4*w.a*P.kf);    // מלפנים/מאחור: מקוצר
const f = Math.floor(wrap1(w.phase) * P.frames) % P.frames;
```

### רגליים על שביל אלכסוני: שתי שכבות
הדמות מורכבת משתי שכבות `<i>` עם אותה תמונה:
- `.up` (ראש וגוף): חתוכה עם `clip-path` מעל הירך.
- `.lo` (רגליים): מתחת לירך, ומוטה עם `skewY` לפי שיפוע השביל.

```css
.m-walker i    { transform-origin: 50% var(--hip); }
.m-walker i.up { clip-path: inset(0 0 calc(100% - var(--hip) - 2px) 0); }
.m-walker i.lo { clip-path: inset(calc(var(--hip) - 1px) 0 0 0); }
```
- ההטיה **רק במבט מהצד**, ומוגבלת ל־`0.35` (כ־19°). יותר מזה הרגליים נראות שטוחות ודו־ממדיות.
- **במבט מלפנים ומאחור אין הטיה בכלל.** הטיה שם יצרה "מסוע" אלכסוני.
- ההטיה משתנה בהדרגה: `w.ky += (tY - w.ky) * min(1, ds/6)`, בלי קפיצות בפניות.

### עצירה והתחלה
- **האטה רכה:** `spf → 0.22`. עוצרים בדיוק כשהרגל שבאוויר מגיעה מתחת לגוף (שלב 0.25 או 0.75), ואז עוברים לתמונת עמידה.
- **יציאה מעמידה:** מתחילים בהרמת רגל (`phase = floor + 0.25`) ומאיצים בהדרגה (`spf = 0.15 → 1`).
- **נשימה בעמידה:** `scaleY(1 ± 0.014)` על השכבה העליונה, במחזור של 3.6 שניות.
- בסוף **ויתרנו על עצירות באמצע הדרך**. המשתמש העדיף הליכה רציפה.

## 4. ניווט על שבילים

- **רשת הליכה:** מסכה בינארית של השבילים (הירוק הבהיר), שנגזרת מהציור ונשמרת כ־bitset ב־base64.
  משאירים רק את רכיב הקשירות הגדול ביותר, כי האיים הקטנים בין האותיות בשלטים הם רעש.
- **A\*:** עם קנס על התרחקות מאמצע השביל (`CENTER_WEIGHT 1.2`) וקנס על מעבר במתחם ההופעות (`FEST_COST 6`).
- **`simplify`:** מקצר את המסלול לקווים ישרים, בתנאי שהם נשארים על השביל.
- **`cleanRoute`:** מסיר קטעים קצרים מ־14 פיקסלים, כל עוד הקו הישר החדש נשאר כולו על השביל.
  בלי זה יש "פניות מוזרות" וזיגזגים קטנים.
- **יעדים מגוונים**, כדי שלא כולם יתרכזו בחלק התחתון של המפה:
  - 15% כניסות למתחם ההופעות: נעלמים בפתח ויוצאים ממנו.
  - 45% מקומות כמו שירותים, בישול, ברזיות ומקלחות.
  - 40% "אוהלים": תאי שביל שצמודים לגוש ירוק כהה.

  בבדיקה התקבלה התפלגות של 27/29/44% בין אזורי המפה.
- **כניסה ויציאה:** הדמות נבלעת ביעד ומופיעה ממנו עם שקיפות לאורך כשנייה של הליכה (`fade = speed*1.3`),
  ומחכה בפנים 8–30 שניות.

## 5. הדמויות: מתכונים

### מטיילים (9 דמויות)
- כל דמות שונה: גובה 52–63, עובי 0.88–1.08, ותוספת אחת: תיק, מעיל ארוך, כובע רחב, כובע מצחייה או קוקו
  (הקוקו מתנדנד בהליכה ומתעופף אחורה בריצה).
- **קצב אישי:** `WALK_PACE = [1, 1, 0.82, 1.18, 0.95, 1.08, 0.9, 1.12, 1.05]`, ומהירות בסיס של 17 פיקסלי מפה בשנייה.
- **זוג:**
  - בן הזוג הולך על אותו מסלול, צעד לצדו (ניצב לכיוון ההליכה) וכ־5 פיקסלים מאחור.
  - בשביל צר הם מתקרבים זה לזה: בודקים מרחקים של 9, 7, 5 ו־3 פיקסלים ולוקחים את הראשון שעל השביל.
  - המרחק משתנה בהדרגה.
  - הצעדים של בן הזוג מחושבים לפי המרחק שלו, והם נושמים לא באותו קצב.

### הנודד עם הבלון
- לא נכנס לשום מקום, ותמיד בוחר יעד רחוק (הרחוק מבין 8 הגרלות), כך שהוא חוצה את כל המפה.
- הבלון הוא SVG נפרד שקשור ליד. בבנייה נשמר מיקום היד לכל תמונה ולכל מבט (`balloonHands[view][frame]`).
- הבלון מתנופף בשני גלים איטיים ונגרר מעט אחורה ביחס לכיוון ההליכה:
  `ang = 9*sin(t*0.9) + 4*sin(t*2.1) - dir*11`.

### הרץ לשירותים
- **תמיד בדיוק רץ אחד על המפה**, ובכל פעם דמות אחרת. הרץ הבא יוצא רק 5 שניות אחרי שהקודם הגיע.
- אם הדמות שנבחרה כבר הולכת, היא משנה כיוון באמצע הדרך ולא נעלמת. אחרת היא יוצאת מהאוהל בריצה.
- **מחזור ריצה אמיתי** (שורות נפרדות בגיליון), ולא הליכה מהירה:
  - `RUN_A 0.16`
  - `RUN_DUTY 0.35`: רגל על הקרקע רק 35% מהמחזור, ויש שלב ריחוף ששתי הרגליים באוויר.
  - העקב נבעט למעלה מאחור, המרפקים כפופים בכ־90°, הגוף נוטה 13° קדימה, והירך קופצת בריחוף.
  - `RUN_D = 2*RUN_A/RUN_DUTY` הוא המרחק לכל מחזור, כך שגם בריצה כף הרגל נעוצה.
- מהירות פי 2.3. **לא מטים את כל הדמות כדי "לרוץ"**: נטייה צריכה להיות בציור, אחרת זה נראה כמו נפילה.

### המעשן
- גיליון של 3 שורות × 9 תמונות: יושב (יד מהברך לפה), עומד (יד מהמותן לפה), קם (וגם מתיישב, באותן תמונות בסדר הפוך).
- כל התנוחות מאותו שלד, עם IK מהירך לכפות הרגליים. בזמן הקימה הגוף נוטה קדימה והירך עוברת מעל כפות הרגליים.
- **מכונת מצבים:**
  1. מנוחה של 3–6 שניות.
  2. היד עולה (0.9 שניות).
  3. שאיפה (1.1–1.7 שניות): הגחלת מתלהטת.
  4. היד יורדת (0.9 שניות).
  5. נשיפה: 4 משבים מהפה.

  אחרי 3–6 מחזורים הוא קם, מעשן בעמידה במשך 6 שניות ומתיישב.
- **רק הגחלת זוהרת** (אלמנט נפרד של 2.4 פיקסלים עם `box-shadow`), ולא כל הדמות.
- **עשן = כדורים קטנים ומסתלסלים** (WAAPI, 9 keyframes), ולא "חוטים":
  - עולים לאט, 34–54 פיקסלים במשך 4.4–6.6 שניות.
  - מתפתלים בגלים שהולכים וגדלים: `sin(ph + u*turns*2π) * (2 + 9u)`.
  - מסתובבים, מתרחבים ונעלמים.
  - מגבלה של עד 40 חלקיקים.
  - **בזמן שאיפה לא יוצא עשן מהקצה.**
- נשימה עדינה ב־CSS: `scaleY(1.018) rotate(-0.8deg)`, במחזור של 4.2 שניות.

### הישן
- SVG פשוט: מזרן, כרית וראש, ושק שינה (`.bag`) שעולה ויורד: `scaleY(1.09)`, במחזור של 4.4 שניות, מהבסיס.
- אותיות z קטנות עולות באלכסון, גדלות ונעלמות. אחת כל 1.7 שניות, והשלישית בכל סבב היא Z גדולה. עד 6 בבת אחת.

### שחקני פריזבי
- **48 תמונות** שנוצרות מ־6 תנוחות מפתח `(נטייה, כיפוף ברכיים, זרוע עליונה, אמה)` עם `ease` קוסינוס:

  | תמונות | מעבר |
  |---|---|
  | 0 | חזה |
  | 1–12 | מהחזה להכנה |
  | 13–20 | מההכנה לשחרור |
  | 21–28 | מהשחרור להמשך התנועה |
  | 29–36 | מעמידה להושטה |
  | 37–44 | מהושטה לחזה (ספיגה) |
  | 45–47 | מהמשך התנועה לעמידה |

- השחקן השני הוא אותה תמונה במראה (`scaleX(-1)`), וגם מיקומי הידיים שלו משתקפים.
- **ציר זמן של זריקה אחת:**
  - הכנה איטית: 0.6 שניות, `easeIn`.
  - הנפה שמאיצה עד השחרור: 0.16 שניות, `u^1.4`.
  - המשך תנועה: 0.35 שניות.
  - טיסה: 1.9 שניות.
  - התופס מושיט יד 0.5 שניות **לפני** ההגעה ומחכה.
  - ספיגה אל החזה: 0.45 שניות.
  - המתנה: 0.9 שניות, ואז הוא זורק בחזרה **מאותה נקודה** שבה הפריזבי נמצא.
- **הריחוף:**
  - **מהירות:** יוצא מהר ומאט בהדרגה: `v = u + 0.16*sin(πu)*(1-0.3u)`.
  - **עילוי:** מטפס מעט באמצע: `lift = 34*sin(π*u^0.85)`.
  - **עומק:** סטייה קלה הצידה.
  - **נטייה:** מתהפכת לאט, עם רעד קטן של סיבוב: `3.5*sin(30u)`, שדועך.
  - **צל על האדמה:** עובר בין כפות הרגליים של שני השחקנים, ומתכווץ ונחלש ככל שהפריזבי גבוה יותר.
- **התפיסה:** הפריזבי נוחת בדיוק ביד המושטת, רועד קלות בכ־0.25 שניות הראשונות, ואז זז יחד עם היד אל החזה.

### ציפורים
- **חיתוך מהציור:** הציפורים מזוהות כפיקסלים כהים בהרבה מהשמיים בגוון כחלחל.
  - שכבת השקיפות (alpha) מורחבת (MaxFilter ו־blur), ובמקום הציפור במפה צובעים את צבע השמיים (החציון של הסביבה).
  - הציפור עצמה נשמרת כשכבה שקופה בצבע מוכהה.
- **המסלול** חוצה את כל המפה ומתפתל: סכום של כמה גלי סינוס עם פאזה אישית לכל ציפור.
  - **מהירות משתנה:** איטית בעלייה ומהירה בירידה, באמצעות משקל זמן לכל קטע.
  - **הטיה לתוך הפנייה**, עד ±14°.
  - **המיקום ממשיך מאותה נקודה** גם אחרי רינדור מחדש: `delay = -(Date.now() % duration)`.
- **נפנוף בפרצים:** 3–4 משקי כנפיים (`scaleY(.32)`) ואז דאייה עם כנפיים פרושות.
  - הציפורים הגדולות מנפנפות לאט יותר ודואות יותר זמן, כמו עופות דורסים.
  - מהירויות: 40, 23.5 ו־20.7 פיקסלים בשנייה.

## 7. ביצועים

- כ־13% מה־main thread כשהמפה פתוחה (Chrome headless במחשב), וכ־1% כשהיא לא פתוחה.
- רק `transform`, `opacity` ו־`background-position`, בלי מאפיינים שגורמים ל־layout. `will-change: transform` על הדמויות.
- מערכת חלקיקים מוגבלת (עשן עד 40, z עד 6), וכל חלקיק מוסר ב־`onfinish`.
- `dt` מוגבל ל־0.1 שניות, כדי שאחרי לשונית ברקע לא תהיה קפיצה.
- בדיקת מגבלות ומעברים רק פעם ב־500 מילישניות (למשל `ensureRusher`), ולא בכל פריים.

## 8. מלכודות קוד שנתקלנו בהן

- **`Math.pow` של בסיס שלילי עם מעריך לא שלם מחזיר `NaN`.** אחרי סוף השלב, `1 - (s-t)/D` שלילי.
  תמיד להגביל את הערך: `cl = u => Math.max(0, Math.min(1, u))`, ולהשתמש ב־`pow(1 - cl(...), k)`.
  - הגבלה גם **בתוך** פונקציית ה־easing: smoothstep מחוץ לטווח 0–1 אינו מונוטוני.
- **אינדקס תמונה לא שלם:** `Math.round` רק לתמונה שמוצגת. למיקום החפץ משתמשים באינטרפולציה בין `floor` ל־`ceil`.
- **בתחילת הלולאה:** בסבב הראשון אין "תפיסה קודמת". לכן התופס מתחיל בעמידה (דגל `first`).
- **גיליון עם כמה שורות:** `background-size: cols*100% rows*100%`, והמיקום האנכי ב־`%` הוא `row/(rows-1)`.
- **שחקן במראה:** `transform-origin` חייב להיות בציר הדמות (`cx%`), ומיקום היד משתקף: `left + 2*cx*w - hx`.

## 9. איך בודקים (Puppeteer)

- **מדידת קפיצות:** בכל `requestAnimationFrame` קוראים את ה־`translate` של החפץ ומחשבים את המרחק מהפריים הקודם.
  - מסמנים כל קפיצה מעל 6 פיקסלים ושומרים את הזמן שלה.
  - כך מאתרים בדיוק באיזה שלב הבעיה, לפי הזמן במחזור.
  - **בפריזבי:** לפני התיקון הייתה קפיצה מרבית של 28.8 פיקסלים בשלב ההכנה, ואחריו 11.6 פיקסלים, רק בהנפה המהירה.
- **הליכה:**
  - 0 קפיצות במיקום.
  - כל נקודה במסלול נמצאת על מסכת השבילים.
  - התפלגות היעדים בין אזורי המפה.
  - "רץ אחד בכל רגע" (59 מתוך 60 שניות).
- **מעשן:** בדיקה שכל 3 השורות הופיעו לפחות פעם אחת ב־90 שניות.
- **צילומי מסך:**
  - מקרבים את המפה ידנית (`map.s = 1.9`, ומרכז על הדמויות) וחותכים אזור קבוע.
  - מצלמים רצף של כ־30 תמונות בהפרש של כ־110 מילישניות ומרכיבים מהן רשת אחת לבדיקה מהירה.
  - **ב־deviceScaleFactor גבוה החיתוך יוצא במקום הלא נכון**, ולכן עובדים בקואורדינטות CSS, או בצילום של כל המסך.
- **גודל הבדיקה לפי השינוי:** שינוי באנימציה דורש מדידה וצילום, לא את כל סט הבדיקות של המערכת.

## 11. הקוד (`code/`)

| קובץ | מה יש בו |
|---|---|
| [`code/sprites.py`](code/sprites.py) | יצירת כל גיליונות התמונות ב־Python ו־PIL: `make_birds` (חיתוך הציפורים מהציור), `make_person` ו־`make_walk_sheet` (הליכה בשלושה מבטים, עמידה וריצה), `make_smoker`, `make_frisbee`. בסוף הקובץ `export_assets(out)` מראה איך הכול מגיע לדפדפן כ־`ASSETS.*` (data URI ו־JSON) |

### מה צריך לספק בפרויקט חדש
- `ASSETS`: האובייקט שמגיע מ־`export_assets`. כולל `mapW` ו־`mapH`, ‏`birds`, ‏`person`, ‏`smoker`, ‏`frisbee`, ‏`walk`, ‏`fest`, ‏`walkW`, ‏`walkH` ו־`walkCell`.
- `PLACES` ו־`PLACE`: נקודות במפה (`{id, mapX, mapY}` באחוזים), וגם `placeXY(p)` שממיר אותן לפיקסלים. משמשים ליעדים (`WALK_SPOTS`) ולכניסות (`GATE_POINTS`).
- `MAP_W` ו־`MAP_H` מגיעים מ־`ASSETS.mapW` ו־`ASSETS.mapH`. הקואורדינטות הקבועות בקוד (למשל `FRISBEE_AT`, ‏`SLEEPER_AT`, ‏`BIRDS`) הן של המפה הזו, ברוחב 3200 פיקסלים.
- **חיבור:** ב־stage של המפה מכניסים את ה־HTML של הדמויות (`birdsHtml()`, ‏`walkersHtml()`, ‏`smokerHtml()`, ‏`sleeperHtml()`, ‏`frisbeeHtml()`),
  ואחרי הרינדור קוראים ל־`flyBirds(stage)`, ‏`walkPeople(stage)`, ‏`smokePeople(stage)`, ‏`sleepZ(stage)` ו־`playFrisbee(stage)`.
  כל אחת מהן נעצרת מעצמה כש־stage מוסר מהדף.
- התגובות בקוד בעברית, כמו בפרויקט המקורי.
